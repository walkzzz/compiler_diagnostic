## 二、问题清单

### Critical（阻断级）

#### C001: JSON 输出数组越界 Bug
- **文件**: `src/output/JSONOutput.cj`
- **行号**: 15, 44, 57
- **问题描述**:
  ```cangjie
  // 第 15 行
  for (i in 0..diagnostics.size) {  // 错误：应该是 0..<diagnostics.size
      ...
      sb.append(this.toJsonDiagnostic(diagnostics[i]))  // 当 i == size 时越界
  }
  ```
  仓颉的 `0..n` 是闭区间 `[0, n]`，当 `diagnostics.size = 3` 时，循环会执行 i = 0, 1, 2, 3，其中 i=3 导致 `diagnostics[3]` 越界访问。
- **影响**: 当诊断数量 > 0 时，JSON 输出会抛出运行时异常
- **修复建议**: 将 `0..diagnostics.size` 改为 `0..<diagnostics.size`（半开区间）
- **验收方式**: 修改后运行 `cjpm test` 确认通过，并添加多元素 JSON 输出测试

#### M002: 缺少 TextOutput 模块测试
- **文件**: `test/UT/`（缺失）

- **影响**: 文本输出格式正确性无保障

#### M003: README 与实现不一致
- **文件**: `README.md` 第 88-105 行
- **问题描述**: README 中的项目结构描述与实际文件不符：
  ```
  ├── src/
  │   ├── Diagnostic.cj              # ❌ 实际文件名为 Diagnostics.cj（复数）
  │   ├── diagnostics/
  │   │   ├── ErrorCode.cj           # ❌ 实际合并到 Diagnostics.cj
  │   │   ├── SourceLoc.cj           # ❌ 实际合并到 Diagnostics.cj
  │   │   └── ...
  ```
  实现时将核心数据结构合并到 `Diagnostics.cj`，但 README 仍描述为分散文件
- **影响**: 新用户阅读 README 会产生困惑
- **修复建议**: 更新 README 中的目录结构描述，与实际代码一致
- **验收方式**: README 描述的目录结构与实际 `find src -name "*.cj"` 输出一致

### Minor（建议级）

#### Mi001: JSON 字符串转义不完整
- **文件**: `src/output/JSONOutput.cj` 第 111-119 行
- **问题描述**: `escapeJson` 方法仅处理了 `\\`, `\"`, `\n`, `\r`, `\t`，但未处理其他控制字符（U+0000-U+001F）
- **影响**: 包含控制字符的 message 会导致输出 JSON 格式错误
- **修复建议**: 添加对控制字符的处理，或使用标准库的 JSON 序列化
- **验收方式**: 添加包含控制字符的测试用例

#### Mi002: getSeverity 函数是死代码
- **文件**: `src/diagnostics/Diagnostics.cj` 第 196-198 行
- **问题描述**: `getSeverity` 函数硬编码返回 `"error"`，且未被任何代码调用
- **影响**: 增加维护负担，可能误导后续开发者
- **修复建议**: 删除该函数，或在 ErrorCode 枚举中添加 severity 字段
- **验收方式**: 删除后构建和测试仍通过

#### Mi003: DiagnosticMessage 构造函数过度重载
- **文件**: `src/diagnostics/Diagnostics.cj` 第 142-193 行
- **问题描述**: `DiagnosticMessage` 有 5 个构造函数重载，调用方难以选择合适参数
- **影响**: API 复杂度高，增加使用错误风险
- **修复建议**: 统一使用 `DiagnosticBuilder` 模式，删除 `DiagnosticMessage` 的 public 构造函数
- **验收方式**: 重构后所有调用点更新，测试通过

#### Mi004: DiagnosticBuilder.setFix 参数类型不一致
- **文件**: `src/diagnostics/DiagnosticBuilder.cj` 第 25-28 行
- **问题描述**: `setFix` 接受 `FixSuggestion`（非 Option），但内部包装为 `Some(fix)`，调用方需理解此隐式转换
- **影响**: API 语义不清晰
- **修复建议**: 直接接受 `Option<FixSuggestion>`，或由调用方决定是否包装
- **验收方式**: API 签名变更需同步更新测试

#### Mi005: BenchmarkResult 字段无验证
- **文件**: `src/benchmark/BenchmarkReport.cj` 第 5-13 行
- **问题描述**: `elapsedMs` 和 `peakMemoryMB` 为 Float64，无正数验证
- **影响**: 负值或 NaN 会导致 `compareWithBaseline` 逻辑异常
- **修复建议**: 在构造函数中添加参数验证
- **验收方式**: 添加边界测试用例
