# 错误码覆盖缺口清单（真实编译器诊断场景 vs 现有 200 码）

> 生成日期：2026-09-04 ｜ 基准：`compiler-diagnostic` commit `7aa5411`（200 规范码 + 8 别名）
> 目的：在「继续扩码」之前，先量化**现有 200 码覆盖了什么、还缺什么**，避免盲目加码。
> 说明：缺口基于标准编译器前端（lexer→parser→sema→type→resolution→codegen→runtime→system）的诊断面评估，并结合本项目 K1「诊断质量提升」目标。部分场景可能已以不同粒度被现有码覆盖，文中以「已覆盖/部分覆盖」标注。

---

## 0. 总体结论（先看这一节）

| 维度 | 评估 |
|---|---|
| **已覆盖度（按场景大类）** | 约 **60–70%**。Lexer/System 骨架最完整；Sema/Type/Codegen/Resolution/Runtime 在细节场景有明显缺口 |
| **比"加更多码"更关键的结构性缺口** | **诊断富信息缺失**：现有 `ErrorMeta` 只有 `template + fix`，**没有** 主/次 spans、related notes、secondary labels、宏展开回溯、suggestions 多候选。这是"诊断质量"项目的核心，比码数更影响可用性 |
| **与真实 cjc 的接线** | 仍缺失：200 码是规范/代表性设计码，**未**与真实 `cjc` 前端各 phase 的报错点 1:1 映射（见上轮结论） |
| **对"开发工具链"的支持** | 已足够（渲染/LSP/文档/CI 均可基于现有 API 建设） |
| **对"当真实编译报错码"的支持** | 不够，需先补缺口 + 建桥接层 |

**建议优先级**：先补 P0 高频必报场景（约 30–40 码即可把覆盖率推到 ~85%），再补结构性的 spans/notes，最后做 cjc 桥接。

## 1. 各类已覆盖度 & 缺口

### 1.1 Lexer（E00xx，25 码）— 已覆盖度 ≈ 80%
**已覆盖**：未闭合字符串/块注释/字符字面量、非法转义、数字格式、非法字符、标识符非法字符、UTF-8、字面量后缀、raw 字符串、BOM、零宽字符、数字分隔符位置、嵌套注释过深、前导零、裸换行、非标准换行。
**缺口（次要）**：
- `P2` 浮点科学计数法 / 十六/八/二进制字面量格式细分错误
- `P2` 字面量最大长度限制（超长 token）
- `P2` Shebang(`#!`) 行处理
- `P2` 多字节字符被截断（surrogate 半截）

### 1.2 Parser（E01xx，25 码）— 已覆盖度 ≈ 60%
**已覆盖**：未闭合字面量、非预期 token、缺分号/冒号、括号不匹配、泛型参数列表未闭合、重复导入、非法顶层、缺类型注解、重复参数名、泛型约束语法、缺返回类型、悬挂文档注释、属性目标非法、可变性冲突。
**缺口**：
- `P1` **模式（pattern）语法错误**（解构/元组/通配位置）
- `P1` 结构体/枚举/接口 **成员声明内部语法**（字段重复、缺字段、可见性修饰符语法）
- `P1` **lambda/闭包表达式语法**（参数列表、箭头、体）
- `P1` **字符串插值 `${}` 语法**
- `P1` `if/match/while` 表达式缺 `else`/缺臂（语法层；语义穷尽已有 E1014）
- `P2` 异步 `async/await` 语法
- `P2` 运算符优先级/结合性歧义（语法层面）

### 1.3 Sema（E10xx，25 码）— 已覆盖度 ≈ 55%（缺口最多之一）
**已覆盖**：未定义符号、重复声明、实参数目、不可变赋值、声明前使用、break/continue、缺返回、不可达、遮蔽、废弃 API、常量未初始化、重复导入定义、非法递归、match 穷尽、不可达 match 臂、泛型推导失败、不可变对象修改、运算符重载签名、接口默认实现冲突、主构造未用参数、不可达循环、转换安全标注、缺 main、trait 冲突实现、不安全逃逸。
**缺口**：
- `P0` **trait 实现缺少方法**（未实现某方法体）——部分由 E3007 覆盖，但"具体缺哪个方法"的细报缺失
- `P0` **闭包捕获环境错误**（捕获了不可逃逸/不可变变量）
- `P0` **函数重载解析失败（非歧义）**——歧义已有 E2004，但"无可用重载"缺
- `P1` **默认参数 / 命名实参不匹配**
- `P1` **可变性传播**（字段 mutability、struct 字段可变性冲突）
- `P1` **抽象/虚方法未实现**
- `P1` **协程/async 语义**（非法挂起点、await 类型约束）
- `P1` **递归 let/const 初始化循环**（除类型层 E2007/E2015）
- `P2` 声明宏卫生性（hygiene）冲突

### 1.4 Type（E20xx，25 码）— 已覆盖度 ≈ 60%
**已覆盖**：类型不匹配、推断失败、非法转换、重载歧义、缺泛型实参、约束不满足、递归别名无大小、栈上不定长、隐式精度丢失、型变、where 不满足、闭包类型、借用冲突、推断循环、协变返回、空枚举、不安全 trait 上转、泛型实参数目、接口循环继承、返回类型不兼容、关联类型、非法 self、HRTB、phantom 不匹配。
**缺口**：
- `P0` **编译期 const 求值失败 / const 溢出**（运行时溢出有 E5005，编译期缺）
- `P0` **可空类型 / Option 解包错误**（未判空直接用、? 类型不匹配）
- `P1` **元组/数组元素类型不匹配细节**（逐元素定位）
- `P1` **函数指针类型不兼容**
- `P1` **字面量类型歧义**（整数字面量既可是 Int64 又可是其他）
- `P2` 异常/错误类型（若有 checked exception 体系）
- `P2` 泛型默认实参缺失

### 1.5 Resolution（E30xx，25 码）— 已覆盖度 ≈ 60%
**已覆盖**：模块未找到、导入项不存在、导入冲突、访问私有、路径无法解析、循环导入、未实现接口、super 非法、顶层名冲突、依赖版本不兼容、宏展开失败、别名循环、导出缺失、传递可见性、cfg 分支未覆盖、宏导入路径、重导出冲突、包初始化循环、cfg 符号未定义、可见性提升警告、导入别名冲突、不稳定 API、缺特性标志、符号优先级冲突、孤立 impl。
**缺口**：
- `P1` **通配导入（glob `*`）冲突/歧义**
- `P1` **宏卫生性 / 声明宏作用域**
- `P1` **更细的可见性层级**（pub/crate/包内/internal 边界错误定位）
- `P1` **trait 方法解析顺序冲突**
- `P2` 条件编译 `cfg` 表达式求值错误（布尔组合）
- `P2` 重命名导入（rename）目标冲突细节

### 1.6 Codegen（E40xx，25 码）— 已覆盖度 ≈ 50%（缺口最多之一）
**已覆盖**：不支持结构、栈溢出风险、非法内建、链接符号冲突、ABI 不兼容、优化内部失败、未初始化使用、常量过大、目标不支持、发射中断、寄存器分配、尾调用、内联失败、常量折叠溢出、目标特性、不可达（优化）、虚表溢出、异常表过大、内联汇编语法、对齐指令、SIMD、调试信息、段过大、重定位、采样插桩。
**缺口（高频关键）**：
- `P0` **泛型单态化失败（monomorphization failure）** —— 真实编译器极常见，当前完全缺失
- `P0` **链接器调用/执行失败**（库缺失、链接器报错）——仅有符号冲突 E4004
- `P0` **内置函数（builtin）目标不支持**
- `P1` **调用约定（calling convention）不匹配**
- `P1` **线程局部存储（TLS）不支持**
- `P1` **FFI / C ABI 签名不匹配**
- `P1` **目标 triple / 架构无效**
- `P2` DWARF/调试格式特定错误
- `P2` 递归单态化导致的代码膨胀中止

### 1.7 Runtime（E50xx，25 码）— 已覆盖度 ≈ 60%
**已覆盖**：NPE、数组越界、除零、栈溢出、整数溢出、转换失败、资源耗尽、死锁、断言、展开中止、move 后使用、数据竞争、缓冲区溢出、无限递归、FFI 失败、析构抛异常、弱引用失效、负索引、非法协程挂起、对齐错误、资源泄漏(警告)、契约破坏、超时、栈损坏、未知致命。
**缺口**：
- `P0` **双重释放（double free）**
- `P0` **释放后使用（use-after-free）细节** —— move 后使用有 E5011，但堆 UAF 未单列
- `P1` **actor / 消息队列满 / 信道关闭后发送**
- `P1` **原子操作误用**（非原子竞争、内存序）
- `P1` **线程数/协程数超限**
- `P2` 内存映射（mmap）失败
- `P2` 信号量/锁递归死锁细节
- （若 Cangjie 用 GC）`P2` GC 相关（晋升失败、碎片）

### 1.8 System（E90xx，25 码）— 已覆盖度 ≈ 75%（最完整）
**已覆盖**：ICE、文件 IO、OOM、超时、配置非法、插件加载、缓存损坏、网络失败、权限、未分类、并发数、诊断序列化、版本不兼容、环境变量、内部断言、临时目录、输出通道、插件版本、中断信号、未知致命、资源上限、特性不支持、致命信号、不可恢复、正常关闭。
**缺口（很少）**：
- `P2` 增量编译缓存失效/重置
- `P2` 远程/分布式编译错误
- `P2` 沙箱/容器资源限制细节

## 2. 跨类结构性缺口（比加码更重要）

> 这一节不是"少几个码"，而是**诊断本身的信息丰富度**——直接决定"诊断质量"项目成败。

| 缺口 | 现状 | 影响 | 优先级 |
|---|---|---|---|
| **主/次源码位置（primary & secondary spans）** | `ErrorMeta` 仅 `template`，无 `startLine/startCol/endLine/endCol` 字段 | 编辑器无法高亮、无法跳转 | **P0** |
| **related notes / secondary labels** | 无 | "在此声明""在此使用"等关联说明缺失，用户难定位 | **P0** |
| **宏/泛型展开回溯（macro/instantiation backtrace）** | 无 | 复杂报错无法展示展开路径 | P1 |
| **多候选 suggestions** | `FixSuggestion` 仅单条，无列表 | 多个修复建议无法并列 | P1 |
| **诊断严重度到 LSP 已映射**，但**诊断分组/规则号**无 | 已映射 LSP severity | 不影响 | — |
| **i18n 文案** | 仅中文 | 若需英文/双语，缺字段 | P2 |

**建议**：在扩码到 ~240–260 的同时，给 `ErrorMeta` 增 `spans: Array<Span>`、`notes: Array<Note>` 字段，并让 `toDiagnostic()`/`toLsp()` 输出它们。这是质量提升的杠杆点。

## 3. 优先级缺口清单（可直接转化为待加码）

**P0（高频必报，建议优先补，约 30–40 码）**
1. Codegen：泛型单态化失败、链接器执行失败、builtin 目标不支持
2. Type：编译期 const 求值/溢出、Option/可空解包错误
3. Sema：trait 缺方法细报、闭包捕获环境错误、重载解析无可用候选
4. Runtime：双重释放、堆 use-after-free
5. 结构性：Span/Notes 字段（跨类，先改 `ErrorMeta` 结构）

**P1（提升真实感，约 30 码）**
- Parser：模式语法、结构体/枚举/接口成员语法、lambda 语法、字符串插值、`else`/臂缺失
- Sema：默认/命名参数、可变性传播、async 语义、递归初始化循环
- Resolution：glob 导入歧义、宏卫生性、可见性层级细化
- Codegen：调用约定、TLS、FFI ABI、目标 triple
- Runtime：actor/信道、原子误用、线程数超限
- 结构性：宏/泛型展开回溯、多候选 suggestions

**P2（边角/内部，按需）**
- Lexer/System 的个别细项、DWARF、增量缓存、远程编译、GC 相关

## 4. 下一步建议（待你确认方向）

- **A. 先补 P0（约 +35 码 + 结构性 spans/notes）** → 覆盖率推到 ~85%，且诊断真正可用
- **B. 先把结构性 spans/notes 加上（改 `ErrorMeta`，不扩码）** → 质量杠杆最大
- **C. 建 cjc 真实诊断 → E 码桥接表** → 让真实报错能吐规范码（上轮已确认缺）
- **D. 维持现状，直接基于 200 码开发工具链**

> 按本项目「诊断质量提升」主旨，**B + A 组合**性价比最高：先让诊断"有位置有备注"，再补高频场景码。
