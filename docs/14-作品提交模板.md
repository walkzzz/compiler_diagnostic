## 一、项目概述

### 1. 项目一句话定位
本项目面向仓颉编译器开发者，提供结构化的诊断输出能力，解决仓颉原生开发中错误信息不清晰、缺少修复建议、IDE 集成困难的痛点，可大幅提升开发者排错效率与编码体验。

### 2. 项目开发背景
当前仓颉编译器诊断系统存在以下问题：
- 错误信息格式不统一，缺少结构化字段
- 缺少修复建议，开发者需自行排查问题
- JSON 输出不符合 LSP 规范，IDE 集成困难
- 错误码体系不完善，回归测试困难

本项目旨在填补仓颉编译器诊断结构化能力的空白，为 IDE 集成和 AI 辅助开发提供标准化接口。

### 3. 项目核心目标
- **基础功能目标**：实现 Parser/Sema 诊断字段结构化、JSON 输出符合 LSP 规范
- **进阶创新目标**：提供修复建议、候选符号、性能基准测试框架

## 三、作品核心能力与功能设计

### 1. 基础通用能力

#### （1）能力一：错误码体系
- **功能介绍**：定义 10 个标准化错误码（E0001-E0005 Parser, E1001-E1004 Sema）
- **适用开发场景**：所有需要错误诊断的开发场景
- **调用方式简述**：通过 ErrorCode 枚举访问，如 `ErrorCode.ParserUnterminatedString`
- **实现效果与价值**：统一错误标识，便于 IDE 和工具解析

#### （2）能力二：结构化诊断消息
- **功能介绍**：DiagnosticMessage 包含 code/severity/message/span/fix/related/candidates
- **适用开发场景**：编译器诊断输出、IDE 错误提示
- **调用方式简述**：`DiagnosticBuilder` 链式构建
- **实现效果与价值**：提供完整错误上下文，加速问题定位

### 2. 创新特色能力

#### （1）创新点一：LSP 兼容 JSON 输出
- **创新详情**：诊断输出符合 Language Server Protocol 规范，可直接对接 IDE
- **相较于同类仓颉库的核心优势**：唯一提供 LSP 兼容输出的诊断库

#### （2）创新点二：修复建议生成
- **创新详情**：FixSuggestion 模块提供可执行的修复建议
- **相较于同类仓颉库的核心优势**：支持一键修复，提升开发者体验

## 四、仓颉语言核心特性应用

### 1. 应用仓颉特性1：Option 类型
- **技术实现与封装逻辑**：使用 `Option<FixSuggestion>` 和 `Option<List<String>>` 表示可选字段
- **落地优势与效果**：避免 null 指针异常，符合仓颉惯用法

### 2. 应用仓颉特性2：Builder 模式
- **技术实现与封装逻辑**：DiagnosticBuilder 提供链式调用，支持 fluent interface
- **落地优势与效果**：代码简洁，API 易用

### 3. 应用仓颉特性3：枚举 match 表达式
- **技术实现与封装逻辑**：ErrorCode 使用 match 表达式返回 code/description
- **落地优势与效果**：类型安全，编译期检查
