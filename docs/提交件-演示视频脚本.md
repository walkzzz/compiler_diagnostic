# 演示视频脚本（compiler-diagnostic）

> 建议时长：3–4 分钟 ｜ 录屏 + 画外音 ｜ 分辨率 1920×1080
> 全程使用 STS Cangjie 1.1.3（cjc 1.1.3 cjnative）+ stdx 1.1.3.1

---

## 分镜 1 · 开场（0:00–0:25）

- **画面**：标题页「编译器诊断质量提升 compiler-diagnostic ｜ 仓颉挑战赛 K1」，下方副标题“结构化诊断 · LSP 兼容 JSON · 性能零劣化”。
- **解说**：大家好，这是仓颉编译器诊断质量提升作品。它让仓颉编译器的报错从“一段话”变成“结构化数据”，可被 IDE、AI 助手直接消费，显著提升排错效率。

## 分镜 2 · 痛点与能力（0:25–0:50）

- **画面**：左右对比。左：传统报错文本（无结构）；右：本作品输出 JSON（code/severity/span/fix）。
- **解说**：传统诊断缺少统一结构与修复建议。本作品提供 10 个稳定错误码（E0001–E1004）、结构化字段、修复建议（fix）与候选符号（candidates），并输出符合 LSP 规范的 JSON。

## 分镜 3 · 构建与运行（0:50–1:40）

- **画面**：终端依次执行 `cjpm build`（显示 exit 0、零警告）、`cjpm run`（文本输出示例）、`cjpm run -- --diagnostic=json`（JSON 输出示例，高亮 span 与 fix 字段）。
- **解说**：构建零警告通过。运行支持文本与 JSON 两种模式；JSON 模式严格对齐 LSP Diagnostic 结构，含起止位置与一键修复建议。

## 分镜 4 · 三层测试（1:40–2:30）

- **画面**：终端执行 `cjpm test`，展示 `TOTAL: 80 / PASSED: 80 / FAILED: 0`（ut 46 · hlt 12 · llt 22）；再执行 `python ci_test/ciTest.py hlt` 与 `... llt` 展示集成/低级测试全绿。
- **解说**：测试覆盖单元（UT）、集成（HLT）、低级（LLT）三层，共 80 个用例全部通过，验证错误码体系与输出格式的稳定性。

## 分镜 5 · 静态检查与规范（2:30–3:10）

- **画面**：终端执行 `cjlint -f src -o cjlint_report.json`，展示报告汇总“MANDATORY = 0”；注释说明 320 条均为 SUGGESTIONS（非阻断）。
- **解说**：通过 cjlint 静态检查，无 error 级（MANDATORY）违规；剩余提示均为风格建议，不阻断赛事门禁。

## 分镜 6 · 收尾与价值（3:10–3:40）

- **画面**：回到标题页，列出三项核心亮点（结构化诊断 / LSP 兼容 / 性能基准），附仓库地址占位。
- **解说**：本作品无外部依赖、纯仓颉实现，已具备提交条件，可立即用于 IDE 集成与 AI 辅助开发。

---

## 录制要点

- 终端字体放大，确保命令与输出清晰可读。
- 关键输出（exit 0、TOTAL 80 PASSED 80、MANDATORY = 0）可适当定格或加高亮。
- 画外音避免念代码，讲“做了什么、为什么有用”。
- 结尾保留 2 秒静帧，便于裁剪。
