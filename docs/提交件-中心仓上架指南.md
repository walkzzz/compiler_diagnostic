# 中心仓上架指南（compiler-diagnostic）

> 将本作品上架至仓颉三方库中心仓的操作步骤与合规检查清单。

---

## 一、前置条件

1. 已安装 STS Cangjie 1.1.3（`cjc 1.1.3 cjnative`）与独立 stdx 1.1.3.1。
2. 已注册仓颉中心仓账号，并配置好 Git 凭证 / 上架鉴权。
3. 本地已通过全部门禁（见下文「二、本地自检」）。

## 二、本地自检（提交前必做）

```bash
cjpm clean
cjpm build                                  # 期望：exit 0
cjpm test                                   # 期望：TOTAL 80 / PASSED 80 / FAILED 0，warning = 0
cjlint -f src -o cjlint_report.json         # 期望：MANDATORY = 0
```

- 确认 `ci_test.cfg` 的 `compile_options` 为 `--test -Woff unused --dy-std`（**非** `-Woff all`）。
- 确认 `LICENSE` 为 Apache-2.0 且内容完整。
- 确认 `README.md` 包含环境要求、构建/运行/测试命令与门禁状态。

## 三、初始化并提交（当前为非 git 仓库）

```bash
git init
git add -A
git commit -m "feat: compiler-diagnostic K1 — 结构化诊断 + LSP 兼容 JSON 输出"
```

> 提交前用 `git status` 确认 `scratch/` 为空、无临时文件混入；`docs/evidence-cjlint-report.json` 可随仓库提交作为客观证据。

## 四、上架中心仓（推荐流程）

1. 在中心仓创建组织/仓库（建议名 `compiler-diagnostic`），可见性按赛事要求设为公开。
2. 关联本地仓库并推送：
   ```bash
   git remote add origin <中心仓仓库地址>
   git push -u origin main
   ```
3. 在中心仓的“上架/发布”入口填写：
   - **名称**：compiler-diagnostic（编译器诊断质量提升）
   - **分类**：技术课题 / 开发工具
   - **版本**：0.1.0
   - **SDK 要求**：STS Cangjie 1.1.3 + stdx 1.1.3.1
   - **简介**：一句话定位（同 README 项目概述）
   - **README**：指向仓库 `README.md`
4. 上传演示视频（脚本见 `docs/提交件-演示视频脚本.md`），并填写视频链接。
5. 提交 PR / 上架申请，等待审核。

## 六、常见问题

- **Q：ciTest.py 提示 “the path 'ut' does not exist”？**
  A：`cjpm test <arg>` 把参数当路径；测试已置于 `src/ut|hlt|llt`，请用 `cjpm test` 或 `python ci_test/ciTest.py ut|hlt|llt`。
- **Q：cjlint 报 “Illegal option: src”？**
  A：正确用法为 `cjlint -f src -o <out>`（不要额外追加尾部路径参数）；`CANGJIE_HOME` 须为 Windows 盘符风格路径。
- **Q：切换 SDK 后构建异常？**
  A：先 `cjpm clean` 再构建（不同 SDK/stdx 版本需清理产物）。
