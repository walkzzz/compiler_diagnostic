# 人在闭环与自学习规则

> 整合自 code_quality_governance_swarm 的 human_in_loop_rules / self_learning_rules。
> 定义治理引擎的人工介入分级与跨项目知识自演进闭环。

## 一、人在闭环（三级介入体系）

设计原则：关键决策不越权、效率优先、渐进式介入、反馈闭环、可配置。

### 强制人工确认（6 点，不可跳过）
| 介入点 | 触发 | 超时 |
|--------|------|------|
| 需求基线确认 | 需求分析交付完成 | 30min→标记风险降档 |
| 架构方案确认 | 架构设计交付完成 | 30min→暂停等待 |
| 带风险通过确认 | 轮次超限策略C | 15min→回退策略A |
| 跨阶段回退确认 | 回退触发 | 15min→自动回退 |
| 总项目终审确认 | 项目门禁完成 | 60min→按判决执行 |
| 紧急修复补审确认 | 紧急修复后 | 24h→标记技术债 |

### 建议人工确认（5 点，可配置自动跳过）
阶段首次通过(auto_advance)、知识入库提升(auto_promote)、规则淘汰(auto_deprecate)、参数调优(auto_tune)、模型替换(auto_replace_model)。

### 自动处理（8 类）
知识提取、灰度入库、规则度量更新、知识老化标记、档位自动升降、阶段自动推进、知识自动检索、冲突自动解决（仅不可自动解决时转人工）。

### 人工反馈回写
approve→规则 success_count+1；reject→false_positive_count+1；modify/supplement→提取为新知识。

介入率监控：强制点维持 100%，建议点逐步降至 20% 以下，自动处理异常率降至 5% 以下；突增触发告警（知识库污染/规则失效）。

## 二、自学习闭环（7 项能力）

项目执行 → 知识提取 → 冲突检测 → 灰度入库 → 老化淘汰 → 度量更新 → 参数调优 → 模型追踪 → 趋势学习 → 跨项目同步 → 下个项目受益。

1. **跨项目知识积累**：全局库（`~/.cangjie-gov/knowledge_global/`）+ 项目库（`./knowledge/`）分层；上行同步 official 级、下行同步按领域标签注入 pending 级；项目专属规则优先于全局。知识标签：domain/language(cangjie)/stage/severity(P0-P2)/source_project/时间戳/计数。
2. **规则有效性度量**：hit/miss/false_positive/fix_effective 计数 → 命中率/精确率/召回率/修复有效率/综合评分 → 驱动排序/降级/淘汰/推荐。
3. **知识老化淘汰**：时间/频次/成功率/版本四维衰减；标记→隔离→复核→删除/恢复；评分<0.1 且 use_count>10 标 deprecated。
4. **参数自调优**：max_round/阈值/成本预算/top_k 依历史调优；微调±10%/中调±20%/大调重估；灰度 10% + 回滚保护。
5. **模型表现追踪**：角色×任务×模型矩阵（首次通过率/误报率/漏检率/token 效率/性价比）；连续 3 次低于均值建议替换。
6. **交付质量趋势学习**：各阶段首次通过率/平均轮次/常见缺陷 Top10；识别高风险阶段生成前置预警。
7. **知识冲突检测**：规则矛盾/重复/过时/案例矛盾/权重冲突；可自动解决(合并/淘汰/降级)否则转人工。

## 三、后置沉淀产物

知识提取 → 三级灰度入库(pending→review→official) → 卷宗归档 → 成本统计 → 交付物追溯链 → 项目完成报告 + 迭代最终报告。
