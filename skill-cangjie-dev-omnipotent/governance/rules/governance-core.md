# 治理核心规则（证据 / 判决 / 风险 / 终止）

> 本文件整合自 code_quality_governance_swarm 的 evidence_rules / judgment_rules /
> risk_level_rules / termination_rules / inspection_rules，是治理引擎（法庭式评审）
> 的裁决依据。所有仓颉交付专家的产出经此规则评审。

## 一、证据优先级（裁决采信顺序）

低位证据不得推翻高位证据。

| 等级 | 内容（仓颉语境） | 裁决效力 |
|------|------------------|----------|
| 一级（绝对） | `cj build` 编译诊断、`cj test` 运行结果、cjlint 静态检查、LSP 诊断、官方 CangjieCorpus 文档原文 | 可作强制判决依据 |
| 二级（强） | 可复现场景验证、官方 API 文档、已上线仓颉生态库案例、行业通用标准 | 可作强制判决依据 |
| 三级（弱） | 经验性判断、风格建议、非权威观点 | 仅可作建议，不可强制整改 |
| 无效 | 无依据断言、虚构 API/规范、杜撰仓颉语法 | 不采纳 |

强制规则：
1. 工具硬校验结论 > 模型共识，模型共识不能推翻 `cj build` / `cj test` 结果
2. 谁主张谁举证，举证不能则指控不成立（疑罪从无）
3. 每条结论必须标注证据等级
4. 三方结论高度一致且无工具支撑时，自动触发二次复核（集体幻觉检测）

## 二、判决规则（法官）

核心原则：
1. **不告不理**：判决范围不超出控方指控范围
2. **疑罪从无**：无有效证据的指控一律不采纳
3. **同证据同判决**：相同证据相同场景判决一致
4. **判决说理**：每条判决写明事实认定、证据依据、判决理由、对应规则条款

判决书强制字段：
- `fact_findings`：事实认定清单（每条附证据等级）
- `judgment`：通过 / 需整改 / 异常终止
- `risk_level`：严重 / 一般 / 轻微 / 无
- `fix_items`：必须整改项（对应严重/一般）
- `suggestions`：建议优化项（对应轻微）
- `reasoning` / `evidence_basis` / `confidence` / `level`

特殊规则：
- 知识盲区标注「该场景经验不足，结论仅供参考」
- 仓颉语法/标准库争议以 CangjieCorpus 语料库检索结果为准，禁止臆造 API

## 三、风险等级与判决动作（四级）

| 等级 | 判定（满足任一） | 动作 |
|------|------------------|------|
| 严重 P0 | 编译失败/运行崩溃（一级证据）；注入/越权/数据泄露；核心逻辑与需求不符；边界完全缺失 | 必须整改，阻断流程，不放行 |
| 一般 P1 | 逻辑缺陷/边界遗漏（二级证据）；异常处理不完整；违反仓颉编码规范；复杂度超标；潜在性能隐患 | 原则上整改；说明理由经总监察长审批可记录放行 |
| 轻微 P2 | 风格/命名/格式；非核心优化；三级证据潜在风险；注释文档缺失 | 记录在案，不强制，后续迭代 |
| 无 | 无有效缺陷证据或指控均被反驳 | 判决通过 |

动态升降档：严重缺陷 ≥2 或存在安全漏洞 → 自动升一档；无一般以上缺陷 → 自动降一档；上限 L4、下限 L0。

## 四、两级监察

- **一级专项监察**：每环节（侦查/指控/辩护/判决）后由对应监察官做即时质检
- **总监察长复核**：判决后独立复核六维度（证据充分性、逻辑一致性、规则适用、风险定级、整改可执行性、成本合理性）
- 监察不改变判决实质时直接放行；发现程序瑕疵退回重做

## 五、终止与迭代

正向终止：四方确认无有效严重/一般缺陷；判决通过且无强制整改；自适应停止（连续 1 轮无新增严重/一般缺陷）。

负向终止：累计告警 ≥3；同一环节重试 2 次仍不合格；用户手动停止；输入致命错误；成本熔断。

迭代触发：判决存在严重/一般缺陷输出整改项；动态升档后补充深度评审。

分支流转：
```
庭审结束 → 法官判决
  ├─ 严重缺陷 → 必须整改 → 退回交付专家修改 → 审判庭重组再审
  ├─ 一般缺陷 → 整改 或 说明理由→总监察长复核放行
  └─ 无/轻微 → 判决通过 → 自动推进下一阶段
```
