## 🔄 动态编排架构 (v7.0 新增)

> 基于 openJiuwen 动态执行框架 (arXiv:2608.27969) 改造
> SWE-bench Verified 82.6%, Terminal-Bench 2.1 87.19%

### 从静态路由到动态编排

| 维度 | v6.0 静态路由 | v7.0 动态编排 |
|------|--------------|--------------|
| 路由方式 | 关键词匹配 → 单技能 | Rail pipeline → 多技能编排 |
| 执行模式 | 单专家直接执行 | Single / Sub-agent / Swarm 三模式统一 |
| 容错 | 失败即返回 | 重路由 / 降级 / 升级 |
| 上下文 | 全量加载 | 渐进披露 + 预算管理 + 压缩 |
| 反馈 | 无 | 运行时证据驱动调整 |
| 经验 | 无 | Self-Reflection + 权重更新 |

### 五大子系统

| 子系统 | 职责 | 对应 openJiuwen |
|--------|------|-----------------|
| Inner Loop | 推理-行动循环 (Think→Route→Execute→Observe) | ReActAgent |
| Outer Loop | 元层监控 (Monitor→Evaluate→Adjust) | Pregel graph |
| Rail | 能力编排 (约束·门控·依赖·契约) | ActionSpec |
| Swarm Flow | 统一单/子/群执行 | 结构化可组合性 |
| Context Engine | 上下文预算·渐进披露·压缩 | context_engine |
| Self-Reflection | 自反思·权重更新·经验记录 | rsi + agent_evolving |

### 8 种 Goal Mode

| Mode | 触发 | 策略 |
|------|------|------|
| normal | 默认 | 直接执行 |
| plan | "规划""设计" | 先规划再执行 |
| code | "写""实现" | 编译验证循环 |
| review | "审查" | 只读分析 |
| debug | "报错" | 复现定位修复 |
| release | "发布" | 检查清单驱动 |
| explore | "了解" | 渐进披露 |
| swarm | 跨3+域 | 多专家并行聚合 |

### Swarm Flow 协作示例

```
"用仓颉写 HTTP 服务器并发布"
  → detect_domains: [framework, net, cicd]
  → select_mode: Swarm (3 域)
  → decompose:
      framework → 服务器骨架
      net → HTTP handler
      cicd → workflow.yml
  → parallel_execute + message_bus
  → aggregate: 合并代码 + workflow
  → reflect: "framework+net+cicd 成功, 权重+0.1"
```

## 🧬 openJiuwen 思想吸收改造 (v8.0)

> **改造日期**: 2026-09-05  
> **架构灵感**: openJiuwen 动态执行框架  
> **SOTA 基准**: SWE-bench Verified 82.6%, Terminal-Bench 2.1 87.19%

### 改造背景

openJiuwen 是一套面向长任务编码智能体的开源动态执行框架，逻辑主线是：

1. **统一的 Inner/Outer Loop 底座** — 把"单智能体、子代理、蜂群流"统一在一套执行语义下（结构化可组合性）
2. **Rail 能力编排** — 横切关注点从业务逻辑中分离，通过 Rail pipeline 注入
3. **Swarm Flow** — 7 个算子 + 模板化多专家协作
4. **运行时自适配** — 在固定模型策略下依据运行时证据动态改写执行

仓颉专家团吸收此四支柱，从 v7.0 的"静态关键词路由"升级为 v8.0 的"Rail 编排 + Swarm Flow + 运行时自适配"。

### 支柱一：执行底座 (Execution Substrate)

**配置文件**: `config/execution-substrate.md`

```
Outer Loop (任务级)
├── Inner Loop (轮次级 ReAct)
│   ├── Expert ←→ Tools (仓颉生态工具)
│   └── Rail Pipeline (11 hooks)
├── continue / resume / stop (运行时证据驱动)
└── 运行时自适配
```

三种执行模式统一：
- **单专家模式**: 一个专家 + 其工具 + 简单 goal check
- **子代理模式**: 路由器作为代理，委托给目标专家
- **蜂群流模式**: 编排专家 + Swarm 算子 + 多专家并行/流水线

### 支柱二：Rail 能力编排

**配置文件**: `config/rails/rail-system.json`

每个 Rail ρ = (H_ρ, f_ρ, p_ρ, g_ρ)：
- H_ρ: hook 集合（11 个 hook 点）
- f_ρ: 执行函数
- p_ρ: 优先级 (10-60)
- g_ρ: 可见性门控

10 个仓颉专用 Rail：

| Rail | 优先级 | 职责 |
|------|--------|------|
| rail-intent-classification | 10 | 意图分类路由 |
| rail-budget-control | 15 | token/时间预算 |
| rail-knowledge-injection | 20 | CangjieSkills 知识注入 |
| rail-delegate-router | 25 | 专家委托 + Swarm 触发 |
| rail-safety-audit | 30 | 国密合规 + 内存安全 |
| rail-runtime-adapt | 35 | 运行时策略调整 |
| rail-quality-gate | 40 | cjlint + cjfmt + 编译检查 |
| rail-cangjie-lsp | 45 | LSP 诊断注入 |
| rail-release-verification | 50 | 多平台构建验证 |
| rail-doc-generation | 60 | SKILL.md + API 文档自动生成 |

### 支柱三：Swarm Flow

**配置文件**: `config/swarm/swarm-flow.json`

7 个算子：`budget` / `parallel` / `compact` / `pipeline` / `agent_session` / `human` / `return`

7 个仓颉专用模板：

| 模板 | Pipeline | 预算 | 人工审查点 |
|------|----------|------|-----------|
| new-project | orientation→framework→tools→doc→cicd | 100K | after_framework |
| feature-dev | router→[compiler\|std]→framework→[sec\|net]→tools→doc | 150K | after_integration |
| bug-fix | router→[runtime\|compiler]→tools→router→tools | 80K | — |
| performance-opt | runtime→[compiler\|std]→tools | 100K | — |
| release-flow | tools→[doc\|release]→cicd→release→comm | 120K | before_release |
| cross-platform-migration | compiler→[runtime\|stdx]→cicd→tools | 150K | after_compat |
| eco-lib-development | orientation→std→framework→[sec\|stdx]→tools→doc→cicd→release | 200K | after_design, before_publish |

### 支柱四：运行时自适配

**配置文件**: `config/runtime/runtime-adaptivity.json`

4 个自适配机制：

1. **Context Management**: 渐进压缩 + 结构感知（按仓颉代码语义块）+ 卸载到 CangjieSkills
2. **Goal Mode**: continue/complete/blocked/resume/stop 五态机，运行时证据驱动转换
3. **LSP 被动反馈**: 仓颉 LSP 诊断 → error 注入修复建议 / warning 标注上下文 / hint 可选优化
4. **Self-Reflection**: 任务完成后提取可复用经验 → 存入 CangjieSkills → 跨任务复用 → 跨专家聚合

### 新增专家：CJ-ORCHESTRATOR

```yaml
代号: CJ-ORCHESTRATOR
名称: 蜂群流编排专家
职责: |
  - 多专家 Swarm Flow 编排
  - budget 控制（token/时间/轮次）
  - parallel/pipeline 调度
  - human-in-the-loop 审查点管理
  - 上下文压缩触发
  - 结果聚合
rail_ids: [rail-delegate-router, rail-budget-control]
capability: { can_delegate: true, can_parallel: true, max_sub_agents: 4 }
```
